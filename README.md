# AgentReady (web)

Paste an Amazon product link. AgentReady reads the product page, shows what an AI shopping agent would take
from it, tests it against shopper prompts (including real Amazon queries from the ESCI dataset), scores
**visibility** and **Amazon SEO**, then proposes a fact-grounded rewrite you can accept and export as CSV or JSON.

Built with Next.js (App Router) for Vercel. No database needed.

## How it works

```
Amazon link ──> /api/analyze
                 1. Rainforest API: title, brand, bullets, description, details, price, rating, image
                 2. ESCI query bank: 20 most similar real shopper queries (keyword retrieval, data/esci_queries.json)
                 3. Claude: what an AI agent extracts + gaps, 5 conversational prompts, 5 Amazon searches
                 4. Claude: judge each prompt with ESCI labels (Exact/Substitute/Complement/Irrelevant) -> R
                 5. Rating model (lib/scoring.ts): V = 0.40 R + 0.30 A + 0.20 C + 0.10 M, plus SEO checklist
            ──> /api/optimize
                 6. Claude: rewrite title/bullets/description using only facts on the page
                 7. Guard (lib/guard.ts): blocks new numbers or risky claims not on the page
                 8. Same prompts, same judge -> projected scores, before/after
Browser   ──> accept or keep original -> download CSV / JSON (generated client-side)
```

Without keys the app still runs: three real ESCI listings work as offline samples, and a keyword-rule judge
replaces Claude (labelled "Judge: keyword rules" in the UI). If a Claude call fails, the app falls back the
same way and says so.

| Path | What |
|---|---|
| `lib/amazon.ts` | Link parsing (product vs category/search/store links), Rainforest client, samples, pasted-text parser |
| `lib/claude.ts` | Three structured-output calls to `claude-opus-5-5` (understand, judge, rewrite) |
| `lib/scoring.ts` | The rating model: R/A/C/M per prompt, clarity rubric, metadata, SEO score |
| `lib/esci.ts` | ESCI query retrieval + labelled examples for the judge |
| `lib/heuristics.ts` | Rule-based fallbacks for every Claude step |
| `lib/pipeline.ts` | `analyze()` and `optimize()` |
| `components/AgentReady.tsx` | The whole UI: Link → Scores → Improve → Export |
| `data/` | Generated by `../app/export_esci_bank.py` from `../ESCI/reduced` |

## Set up (what you need to do)

1. **Anthropic API key**: console.anthropic.com → API keys. Each analysis makes 2 Claude calls, and each
   improvement makes 2 more.
2. **Rainforest API key**: sign up at rainforestapi.com (Traject Data). One product lookup costs 1 credit;
   new accounts get trial credits. Note: these APIs collect data from Amazon pages, which Amazon's terms
   restrict. For a commercial launch, plan to move to Amazon's official **Selling Partner API** (Catalog
   Items) for sellers' own listings.
3. Local run:
   ```bash
   cp .env.example .env.local   # then paste both keys into .env.local
   npm install
   npm run dev                  # http://localhost:3000
   ```
   After editing `.env.local`, restart `npm run dev` (it keeps old values in memory).

## Deploy to Vercel

1. Put this folder in a GitHub repo (it already has a local git repo from create-next-app):
   `git add -A && git commit -m "AgentReady web" && git remote add origin <your repo> && git push -u origin main`.
2. vercel.com → Add New → Project → import the repo. Framework is detected as Next.js. If the repo
   contains the whole Vibathon folder, set **Root Directory** to `agentready-web`.
3. Settings → Environment Variables: add `ANTHROPIC_API_KEY` and `RAINFOREST_API_KEY` (Production and Preview).
4. Deploy. You get a URL like `https://agentready-<you>.vercel.app`.

Notes:
- API routes set `maxDuration = 60` seconds. Two Claude calls usually fit; if you see timeouts, raise it
  on a paid Vercel plan, or lower latency by switching `MODEL` in `lib/claude.ts`.
- The site is public and every analysis spends your API credits. Before sharing widely, add rate
  limiting (e.g. Vercel Firewall rules or Upstash Ratelimit) or a simple password.

## Do you need a database?

Not for the MVP. Every analysis is computed in one request, the browser holds the result, and the export
is generated in the browser. The ESCI query bank (2.7 MB) ships with the app.

Add one when you want any of these:
- **Cache product lookups and Claude results** (saves credits when the same ASIN is analyzed again):
  Upstash Redis from the Vercel Marketplace, keyed by ASIN + date.
- **History, accounts, shareable report links:** Postgres (Neon or Supabase via the Vercel Marketplace).
- **Smarter ESCI retrieval:** Postgres + pgvector, storing embeddings of the 97k queries for semantic search
  instead of keyword overlap.

## How the Amazon ESCI dataset is used

1. **Real shopper queries.** 97,193 real US Amazon queries (`data/esci_queries.json`) are matched to each
   listing. Claude is told to reuse them, and the UI marks prompts that are real ESCI queries.
2. **Relevance definitions.** The judge uses ESCI's Exact / Substitute / Complement / Irrelevant labels
   with 11 labelled ESCI examples (`data/esci_examples.json`), so "relevance" means what Amazon's annotators meant.
3. **Offline samples.** Three real ESCI listings (`data/samples.json`) for demos without a product API.
4. **Benchmark (next step).** The trained Python model in `../app` reached NDCG@10 0.73 on held-out ESCI
   queries. Running Claude's judge on a few hundred held-out ESCI pairs and reporting its agreement with the
   labels would validate R the same way.
